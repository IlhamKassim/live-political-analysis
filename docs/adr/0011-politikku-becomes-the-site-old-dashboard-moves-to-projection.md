# PolitikKu becomes the site; the old dashboard's content moves to `/projection/`, not away

Since #69, PolitikKu (homepage, landing, constituency lookup, MP profiles) and the original dashboard (`public_page.py`) have existed side by side, but only the original dashboard was ever actually deployed — `daily.yml` never built or published any PolitikKu page. We decided PolitikKu takes over the site root, and the original dashboard's analytical depth (full seat ledger, sensitivity table, Majority-margin trend, tipping point, "Too close" module, per-state rollup, full methodology, and the dated-permalink citation archive from #55) is ported into PolitikKu's visual register as a linked detail page at `/projection/`, rather than dropped.

The alternative considered was letting PolitikKu's simpler homepage summary be the entire public site going forward. Rejected because `CONTEXT.md`'s own Audience definition already names a second reader ("an existing politically-engaged reader who would seek the dashboard out regardless") that the dropped content was serving — see the new Engaged Reader term. Dropping it would be a real scope cut, not a redesign, and nothing about PolitikKu's own scoping (#69 named this content "out of scope... link targets only," i.e. deferred, not rejected) intended that.

Cutover is staged, not a big-bang flip: it happens once every PolitikKu page (including `/projection/`) is functionally correct and degrades honestly wherever real data (MP profiles, bills, postcode index) is still pilot-scale — not gated on that data being complete. Full-coverage data ingestion is tracked separately and does not block going live.
